# Project structure (Paper 1.21.11, Java 21)

Target: **Paper 1.21.11**, not 1.8.8. Old-school play comes from per-kit **1.8 combat** (`combat/LegacyCombat.java`), so
1.8 and modern kits run on one server with normal 1.21 clients.

```
vortex-realm/
  practicepvp/                 the plugin source (PracticePvP, package net.practicepvp) — edit here
    src/main/java/net/practicepvp/
      queue/      QueueManager, Matchmaker (ranked/unranked 1v1 queues, Elo + ping windows, tier gaps)
      rank/       EloCalculator, RankManager (Elo, tiers LT5..HT1, seasons)
      data/       async storage: SQLite or MySQL (HikariCP), profiles, settings
      kit/        Kit, KitManager, DefaultKits (incl. the eight 1.8 kits), KitLayout (saved layouts)
      gui/ dialog/ kit editor (chest GUI + 1.21 dialogs), queue menus, admin menus
      match/      PreMatch -> Match state machine: cages/elevator countdown, fight, rounds, stats, rematch
      arena/      ArenaManager, ArenaGenerator, BlockJobs (time-sliced building), arena reset after each match,
                  ArenaSeal (invisible walls to the sky), isolated arena copies per match
      combat/     LegacyCombat (1.8 combat), FightExtras (auto GG, kill sounds, death recap, fight HUD)
      build/      the designed builds (Voxels): court arenas, arcade arenas, lobbies, Club Spawn, Legacy Hall
      bot/        practice bots, Bot Hall, VexBotBridge (optional VexBot bots)
      plus/       the 40+ extra systems (arcade, clans, ladder, pass, replays...)
      lobby/ npc/ cosmetics/ smp/ ...
    src/test/java/             JUnit 5 tests: EloCalculatorTest, MatchmakerTest, KitLayoutTest
  vortexrealm/                 generated by tools/make_vortex.py (VortexRealm, net.vortexrealm) — do not edit
  schematics/                  .schem (Sponge v3) exports of the designs, for WorldEdit / FAWE
  datapack/vortex_practice/    .mcfunction scripts: barrier ceilings/walls, spawn markers, 1.21.11 gamerules
  tools/                       make_vortex.py, make_update_json.py, preview renderers, schem/SchemExport.java
  dist/                        released jars + update.json (auto-update)
```

## How the asked-for pieces map to the code

| Asked for | Where |
|---|---|
| Ranked / unranked 1v1 queues, Elo | `queue/`, `rank/EloCalculator.java` |
| Async SQLite / MySQL | `data/` (all writes off the main thread) |
| GUI kit editor | `gui/menus/KitEditorMenu.java`, `/kiteditor` |
| Duel state machine (countdown cages -> match -> summary + teleport) | `match/PreMatch.java`, `match/Match.java` |
| Isolated arena instances | `arena/ArenaManager.java` (copies per map, acquire/release) |
| Arena reset after every match (blocks, crystals) | `arena/` block tracking + rebuild jobs (no FAWE needed; lighter than a paste) |
| 60x60 duel, 70x70 crystal pit, 15x15 sumo, lobby | generated in game; exported in `schematics/` |
| Barrier ceilings, spawns, gamerules | done by the plugin; `datapack/` for hand-made maps |
| Tests | `practicepvp/src/test/java` — `mvn test` |

FastAsyncWorldEdit is not required: arenas are built and reset by the plugin's own time-sliced jobs. The schematics
are there for anyone who wants to paste a map with WorldEdit/FAWE.
