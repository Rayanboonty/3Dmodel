# VortexRealm – handoff for the next AI agent

Read this first. It is everything you need to take over: the server, the repo, how to build and release, where
things live in the code, what happened so far and what is still open.

## 1. Who / what

- **Server:** the user's Minecraft server on **Bao Host** — `vortexsmps.playwithbao.com`, **Paper 1.21.11**,
  offline mode with **AuthMe**, **low memory** (out-of-memory crashes have happened; keep everything light).
- **VortexRealm** is the main jar: **Practice (MCPVP-style ranked duels, tiers, FFA, bots, lobby) + SMP (homes, tpa,
  rtp, warps, trade, market…) in one plugin.** This is what runs on the server.
- **PracticePvP** is the same code under the old name (`net.practicepvp`, `practice.*` perms, `pp_*` tables). It is the
  **source of truth**; VortexRealm is generated from it.
- **VortexSMP is retired** (merged into VortexRealm in 3.8.0). Its update entry tells servers to remove it.

### Network (important)

Building needs the Paper API and PlaceholderAPI. Their Maven repos (`repo.papermc.io`, `repo.extendedclip.com`) are
blocked in the default cloud environment, and the user declined allowing them. **Workaround (works, tested):**
`bash tools/build_paper_api.sh` builds paper-api 1.21.11 from PaperMC's public GitHub source (tag 1.21.11) plus
Brigadier from GitHub, with every other dependency from Maven Central, adds a PlaceholderAPI compile stub, and installs
all of it into `~/.m2` (with a `~/.m2/settings.xml` that mirrors the blocked repos to Central). Takes about 2 minutes.
A jar built this way was byte-identical to the released 3.9.2.

## 3. Build

From `vortex-realm/` (on a fresh cloud machine run `bash tools/build_paper_api.sh` once first):

```bash
mvn -q -o package -DskipTests -pl practicepvp     # drop -o on a fresh machine (empty ~/.m2)
python3 -I tools/make_vortex.py                     # regenerate vortexrealm/ from practicepvp/
mvn -q -o package -DskipTests -pl vortexrealm
# -> practicepvp/target/PracticePvP-2.x.y.jar, vortexrealm/target/VortexRealm-3.x.y.jar
```

**Version bump:** change only `practicepvp/pom.xml` line 9 (`<version>2.x.y</version>`). `make_vortex.py` reads it and
writes `3.x.y` into `vortexrealm/pom.xml` by itself (major + 1).

**About make_vortex.py:** the original script lived only in the first agent's scratchpad and was lost. It was rebuilt on
Nov 17 2026 from the committed output and **reproduces `vortexrealm/` 3.9.2 byte for byte from `practicepvp/` 2.9.2**
(checked with `git status` after a run: no differences). What it does: renames the package and main class, `pp_*` →
`vr_*` tables, `practice.*` → `vortex.*` permissions, `PracticePvP` → `VortexRealm` in Java, `database.name` default
`vortexrealm`, PlaceholderAPI id `vortex`, backup folder `VortexRealm-2-Vault` (in `DataVault` only), adds the
"PracticePvP is installed too" guard, `VortexMigration.autoMigrate()` and the `/vortex` command, and fixes plugin.yml /
messages.yml / default-kits.yml / admin.html texts. Every patch uses an exact match and stops with "patch failed" if
the source changed under it — then update the patch in the script.

After running it, `git diff --stat vortexrealm` should only show the changes you made in `practicepvp/`.

## 4. Release / auto-update

1. Build both jars (above). Copy them into `dist/` as `PracticePvP-2.x.y.jar` and `VortexRealm-3.x.y.jar`.
2. Edit `NOTES` in `tools/make_update_json.py` (one short line per plugin; keep the VortexSMP "remove this plugin" note).
3. `python3 -I tools/make_update_json.py` → rewrites `dist/update.json` with the newest jar of each plugin + SHA-256.
4. Append the two jars to `dist/SHA256SUMS`: `cd dist && sha256sum PracticePvP-2.x.y.jar VortexRealm-3.x.y.jar >> SHA256SUMS`.
5. Add a `## 3.x.y / 2.x.y — title` section at the end of `README.md`.
6. Commit with the message style `VortexRealm 3.x.y / PracticePvP 2.x.y: what changed`, ending with the attribution
   trailer lines your session gives you (`Co-Authored-By: …` and `Claude-Session: …`).
7. `git push -u origin claude/vortex-realm-pvp-plugin-2x1tq1` — retry up to 4 times with backoff on network errors.
8. Send the user the new `dist/VortexRealm-3.x.y.jar`.

Servers read `update.json` from
`https://raw.githubusercontent.com/Rayanboonty/3Dmodel/refs/heads/claude/vortex-realm-pvp-plugin-2x1tq1/vortex-realm/dist/update.json`
(`update/AutoUpdater.java`): it downloads the jar, checks the SHA-256, puts it in the update folder and restarts when
nobody is online. **`/pvpadmin update`** checks and installs right away. So a push to the branch = an update on the server.

## 6. Admin commands cheat sheet

- `/pvpadmin` (`/pa`) — admin panel (settings, kits, arenas, SMP page, Data Vault, ranks…)
- `/pvpadmin update` — check `update.json` and install now
- `/pvpadmin selftest` · `health` · `reload`
- `/pvpadmin backupall` / `fullbackup` / `fullrestore` / `vault` / `backups` / `restore` — Data Vault
- `/pvpadmin invbackup` / `invbackups` / `setinv` — inventory backups
- `/pvpadmin kitbackup` / `kitrestore` · `settingsbackup` / `settingsrestore`
- `/pvpadmin smp` — SMP page · `/pvpadmin smp link <world> [smp]` / `unlink <world>` / `links`
- `/pvpadmin regenerate confirm` — delete + rebuild every designed (non-vanilla) duel and FFA arena, then walls
- `/pvpadmin arenas enableall` · `arena …` · `walls` (rebuild all walls) · `walls off` · `rebuild` · `vanilla`
- `/pvpadmin setlobby` · `forcelobby` · `hub` · `winter` · `bothall [remove]` · `tabdesign <name>` · `maintenance`
- `/pvpadmin elo|tier|skill|ranked|unranked <player> …` · `player <name>` · `staff`
- `/vortex [migrate]` (VortexRealm only) · `/ai` · `/ecospawn` · `/smpadmin`, `/setspawn`, `/setwarp`, `/delwarp`
- Permissions: `vortex.*` in VortexRealm (`practice.*` in PracticePvP), SMP uses `vortexsmp.*`.

## 10. Testing how-to

- Local Paper test server: download Paper 1.21.11 (needs `api.papermc.io` / `fill-data.papermc.io` allowed), put the jar
  in `plugins/`, run with `-Xmx1G` to imitate the host's low memory, `online-mode=false` in `server.properties`.
- Bots: `npm i mineflayer`, connect with an offline username to `localhost:25565`, script joins / commands / inventory checks.
- In game: `/pvpadmin selftest` runs the built-in checks; the upgrade report is in `plugins/VortexRealm-2-Vault/last-update.txt`.
- Before releasing, at least: build passes, `make_vortex.py` runs without "patch failed", server starts with no SEVERE
  in the log, `/pvpadmin selftest` is green.
